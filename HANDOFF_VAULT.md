## 2. Contracts the Vault app should reuse (do not re-invent)

### 2.1 localStorage keys (PWA, same origin) — for the "reads legacy localStorage and imports automatically" step
| Key | Value | Notes |
|---|---|---|
| `bb_khata` | `Entry[]` | `{id, name, phone, amount, relation, status:'pending'|'paid', dueDate:'YYYY-MM-DD', paidAmount, reminderCount, lastReminderAt, language, tone, note, message, createdAt, updatedAt, transactions?: Tx[]}` where `Tx = {id, type:'gave'|'received', amount:number, date:'YYYY-MM-DD', note, mode, createdAt}` (transactions are lazily created from `amount`/`paidAmount` when missing) |
| `bb_history` | `Msg[]` | `{id, message, name, amount, language, tone, createdAt}` |
| `bb_settings` | object | `defaultLanguage, defaultTone, emojiEnabled, watermarkEnabled, upiId, upiName, businessName, businessPhone, businessAddress, businessGstin, …` |
| `bb_invoices_v1` | `Invoice[]` | `{id:'inv-…', number, date, dueDate, seller, sellerPhone, sellerAddress, gstin, buyer, buyerPhone, buyerAddress, taxRate, discount, note, items:[{description, qty, rate}], payments:[…]}` |
| `bb_hisaab_v1` | `{books:[{id,name,icon}], entries:[{id, bookId, type, amount, name, purpose, date, status:'open'|'posted', createdAt}]}` | default books `business`, `home` |
| `bb_pro_unlocked`, `bb_pro_plan`, `bb_pro_receipt`, `bb_pro_phone` | strings | Pro state; plans `shagun` ₹29 / `pro` ₹99 / `business` ₹249 |
| `bb_last_backup`, `bb_last_restore`, `bb_cookie_consent`, `bb_daily_gen_*` | strings | housekeeping |

### 2.2 Backup JSON (APK import path)
`backup.js` exports `{"app":"BaatBanao","version":1,"exportedAt":ISO,"data":{<key>:<value> for the 5 data keys above}}`. Accept exactly this (and `version:1`) in the Flutter importer; the PWA validates the same way.

### 2.3 URLs
- `/pay?pa=<upi>&pn=<name>&am=<amount>&cu=INR&tn=<note>` — public payment landing (QR + "Open UPI app"); `noindex`. Keep the parameter names.
- `/vendor/qrcode.js` — on-device QR (qrcode-generator 1.4.4, MIT). All QR generation moved on-device in v1.0.70; the privacy policy now promises this — do not reintroduce third-party QR image APIs.
- SEO pages (16 guides + `/guides` hub + info pages) are static HTML on `www.baatbanao.shop`; they are the brand's search equity. They are generated by `seo/generate_pages.py` → `seo/enhance_pages.py`; never hand-edit them.

## 3. SEO rules for the Vault launch (from `main`'s perspective)

1. **Keep `www.baatbanao.shop` as the content/SEO origin.** Serve the Flutter web build at `app.baatbanao.shop` as planned; do not replace `/` on www until 301s + canonical updates are planned.
2. Add a Vault landing page (`/vault`, indexable, with schema + featured image) through the same pipeline: add the slug to `PAGES` in `seo/enhance_pages.py`, drop a 1200×630 JPG in `assets/blog/`, run the two scripts (sitemap regenerates).
3. When the PWA gets the "upgrade banner", keep it below the fold on guide pages (AdSense: no interstitials / no misleading buttons).
4. If PWA routes ever move, keep `/pay` working — it is embedded in already-sent WhatsApp messages.
